Asciimoji is an Expo / React Native app for iOS and Android: a grid of ASCII emoji, tap one to copy it. Prioritize mobile-first patterns and cross-platform behaviour.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. Before writing code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt and follow its links to the specific page; never answer from memory.

## Commands

```bash
npm ci                      # install exactly what package-lock.json pins
npx expo install <package>  # ALWAYS use instead of npm install — resolves SDK-compatible versions
npx expo start              # dev server (web at http://localhost:8081)
npm run lint                # expo lint
npm run typecheck           # tsc --noEmit
npm test                    # jest (jest-expo + expo-router/testing-library)
npx expo-doctor             # dependency and config checks
```

Run lint, typecheck and tests before declaring a task done.

## Layout

- `src/app/` — Expo Router routes only. `index.tsx` is the grid, `menu.tsx` is a modal route, `_layout.tsx` is the stack. Never put tests or helpers here; every file is a route.
- `src/components/`, `src/constants/`, `src/data/` — everything that is not a route. `src/data/emoji.ts` is the emoji list.
- `__tests__/` — Jest tests. `renderRouter` installs Jest fake timers itself, so advance time with `jest.advanceTimersByTime` and do not call `jest.useRealTimers()` between router tests (it stalls the next render).
- `assets/` — imported as `@/assets/...`; `src/` is `@/...`. Keep the `@/assets/*` path first in `tsconfig.json`, Jest resolves the first match.
- `ios/` and `android/` are generated by `npx expo prebuild` and git-ignored. Never edit them by hand; change `app.json` or config plugins instead.

## Platform notes

- Android 13+ shows its own clipboard confirmation, so the in-app "Boom, copied." toast is skipped there (`SYSTEM_CONFIRMS_COPY` in `src/app/index.tsx`).
- Web is a development preview, exported as a single-page app (`web.output: "single"`), because the column count depends on the window width.

## Cursor Cloud specific instructions

Cloud agents run on Linux. Web and Android can be run and seen here; iOS cannot.

### Web

`npx expo start` in a tmux session, then open http://localhost:8081.

### Android emulator

The environment ships the Android SDK in `~/Android/Sdk`, JDK 21 and an AVD named `asciimoji` (Pixel 6, API 35) with Expo Go for SDK 58 cached.

```bash
scripts/android-emulator.sh                      # boots the AVD, waits until Android is ready (~30 s)
npx expo start --go                              # in tmux
adb shell am start -a android.intent.action.VIEW -d exp://10.0.2.2:8081 host.exp.exponent
```

- Drive it with `adb shell input tap|swipe|keyevent`, find coordinates with `adb shell uiautomator dump`, capture with `adb exec-out screencap -p > shot.png` and `adb shell screenrecord`.
- Verify a copy by pasting somewhere real: `adb shell am start -a android.settings.APP_SEARCH_SETTINGS && adb shell input keyevent 279`.
- Expo Go draws a floating gear button over the top-right corner, on top of the menu button. Tap the menu button near its right edge or drag the gear away; it does not exist in real builds.
- First launch of Expo Go opens its developer menu; dismiss it before testing.

### Native Android build

```bash
export ANDROID_HOME=$HOME/Android/Sdk
npx expo prebuild --platform android --no-install
(cd android && ./gradlew assembleDebug -PreactNativeArchitectures=x86_64 && ./gradlew --stop)
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Gradle and its Kotlin daemons hold about 8 GB after a build. Together with the emulator that exhausts the 15 GB VM and the kernel kills the emulator, so build with the emulator stopped (`adb emu kill`) and always run `./gradlew --stop` before booting it again. A debug build still loads its JavaScript from the dev server on port 8081.

### iOS

There is no macOS, Xcode or iOS Simulator here, so an agent cannot render the iOS app. What can be checked locally is that the iOS JavaScript bundle builds: `npx expo export --platform ios`. Say so plainly in summaries instead of implying iOS was seen. Real iOS review needs an Expo Build made on Expo's servers (`npx eas-cli@latest ...`), which requires an `EXPO_TOKEN` secret; the App Store version of Expo Go stops at SDK 54 and cannot open this project.
